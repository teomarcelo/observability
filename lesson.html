Chapter 1

Setup — Observability Toggles

Setup → Einstein & AI → Agentforce Observability — master controls for every layer of visibility
What this screen is: The master control panel for observability across all Agentforce agents and Einstein AI features. Each toggle activates a distinct layer of visibility — from raw audit logs to real-time health alerts. Layers are cumulative: enabling a higher-level toggle often auto-enables the ones below it.
Off

Audit and Feedback

"Collect and store Einstein generative AI audit and feedback data for analysis and reporting."
What it is
Activates collection and storage of every Einstein AI interaction — what was asked, what was returned, and any feedback users gave on response quality.
Purpose
Creates a permanent, queryable paper trail of AI activity in the org — the foundation for compliance and quality investigation.
Why it matters
Without this on, you have zero record of what the AI did. With it on, you can investigate complaints, prove compliance, and identify patterns in poor outputs.
Real-World Use Case

A customer escalates: "the AI gave me wrong information last Tuesday." With Audit on, you pull that exact session and see precisely what prompt was sent and what the model returned.

Off — Nested

Knowledge / RAG Quality Data and Metrics

"Monitor retrievers to track run-time performance, view trends, and identify opportunities to improve results."
What it is
Monitoring layer specifically for the retrieval-augmented generation (RAG) pipeline — the step where the agent searches Knowledge articles before generating a response.
Why it matters
RAG quality is the #1 variable in agent answer quality. Most "hallucinations" are actually retrieval failures — the model answered confidently using the wrong article.
Real-World Use Case

Agent answers keep being slightly off. RAG Metrics reveal the retriever ranks a stale 2021 Knowledge article above the updated 2025 version. Fix the article metadata — fix the answers.

Retired — Summer '26

Prompt Builder Usage and Feedback Metrics

"Prompt Performance Metrics retired in Summer '26 and can't be re-enabled."
What it was
Tracked performance of prompts built in Prompt Builder — which prompts performed well, which generated poor outputs, and usage volume over time.
Instructor note — tombstone: This feature is gone as of Summer '26 and cannot be re-enabled. Point it out explicitly — students will encounter it in older orgs and outdated documentation. Its presence is a reminder that the platform evolves fast and feature availability is release-dependent.
On

Agentforce Session Tracing

"Capture and store detailed interaction data for all agents — reasoning engine executions, actions, prompt/gateway inputs and outputs, error messages, and agent responses."
What it is
The master toggle for Agentforce observability. Captures the complete lifecycle of every agent session — reasoning steps, actions taken, prompt inputs/outputs, error messages, and final responses.
Purpose
Gives you a full "replay" of what any agent did from start to finish, including every decision the reasoning engine made. Provisions the Session Tracing Data Model (STDM) in Data Cloud — the foundation all other analytics depend on.
Why it matters
Without this, agents are a black box. Required to unlock Agent Analytics, Agent Optimization, and Agent Health Monitoring. Enabling it automatically turns on Agent Optimization.
Real-World Use Case

An agent escalated a case it should have resolved. Session Tracing lets you replay the exact reasoning step that triggered the escalation — was it a missing topic, a misconfigured action, or a bad retrieval result?

Off — Developer Tool

Agent Platform Tracing

"Deep insights into every Platform Action — Flow, Apex — within an agent's workflow. Data stored in Data Cloud."
What it is
Captures OpenTelemetry-based spans for every instrumented service in an agent transaction: planner steps, LLM calls, knowledge references, Prompt Builder templates, Flow executions, and Apex invocations. ~2-minute SLA to Data Cloud.
Key distinction
Session Tracing = what the agent decided. Platform Tracing = what the platform did in response — exact durations, execution paths, errors. This is the engineer's tool for finding bottlenecks.
Requirements
Data Cloud provisioned + PlatformObservability org permission + Access Agentforce Optimization permission set. GA as of April 2026.
Real-World Use Case

Agent responses take 8 seconds. Platform Tracing shows the Apex action it called took 7.2 of those seconds. The AI reasoning was fast — the bottleneck was entirely in custom code.

On — Auto-Enabled

Agent Optimization

"Identify gaps in agent performance — categorizes user interactions by intent to spot trends and understand user needs at scale."
What it is
AI-powered analysis layer that categorizes interactions by user intent at scale. Powers the Insights, Sessions & Intents, and Health Monitoring views in Agentforce Studio.
New metrics
Spring '26 additions: User Feedback (Positive/Negative), Task Resolution Rate, Instruction Adherence Rate, Average Toxicity Score, Session Outcome (abandonment/deflection), and Custom Scorers (Beta).
Auto-on
Turns on automatically when Session Tracing is enabled — it cannot function without the session data Session Tracing captures.
Real-World Use Case

5,000 sessions this week. Optimization flags 340 show users re-asking the same question in different ways — a clear signal the agent isn't resolving the intent on first try. Now you know exactly which topic to fix.

Off — Nested

Agent Health Monitoring

"Track agent performance in near-real time with metrics, reporting, alerts, and trace logs."
What it is
Near-real-time performance tracking with configurable metrics, dashboards, alerts, and trace logs for all agents in the org.
Key distinction
The other features above are forensic — they tell you what happened. Health Monitoring is operational — it tells you what's happening right now and alerts before users notice.
Real-World Use Case

A bad deployment at 2am spikes agent error rates. Health Monitoring fires an alert before a single user calls in. The on-call team rolls back and most customers never notice.

Chapter 2

Feature Comparison & Course Setup Flow

Understanding which feature does what — and why the course skips the legacy toggle
Why this matters: The Agentforce observability umbrella has four distinct features. Students often confuse them — especially because "Agent Analytics" is the name of both the old legacy feature and the new dashboard. Knowing the difference prevents setup mistakes in the org.
Feature Purpose Primary Audience Status
Agent Analytics (Legacy) Original usage & engagement data collection in Data Cloud Admins / Analysts ⚠ Retiring May 2026
Agentforce Session Tracing Full session capture — provisions STDM in Data Cloud. Master toggle. Everything depends on this. All roles ✅ GA — enable first
Agent Platform Tracing Low-level OpenTelemetry spans for Flow, Apex, LLM calls. Pinpoints performance bottlenecks. Developers ✅ GA (Apr 2026)
Agent Optimization AI-powered intent analysis & quality scoring. Auto-enabled with Session Tracing. Admins / Analysts ✅ GA — auto-on

Course Setup Flow — Why It's Built This Way

Step 1
Set Up Your Instance — Enable Agentforce Session Tracing (starts capturing data). The legacy Agent Analytics toggle is intentionally skipped — this course teaches the new stack only.
Step 2
Exercise 1, Task 3 — Install Tableau Next analytics app packages for Service Agent and Employee Agent. These are the pre-built dashboards that visualize the session data captured by Session Tracing.
The flow
Session Tracing captures the data → Data Cloud stores it via the STDM → Tableau Next dashboards surface it visually. Without the packages, there's nothing to view the data in.
Common student confusion: "Why don't we turn on Agent Analytics?" — Because the legacy toggle shares a name with the new experience but is a different feature entirely. This course only uses Session Tracing → STDM → Tableau Next. The legacy toggle is not part of that stack.

Agent Analytics Dashboard — Overview Tab

High-level health check: adoption, effectiveness, and customer behavior at a glance
What this tab answers: Are users actually engaging with the agent? Is it resolving issues or are people just leaving? This is the first tab an admin or analyst should check — it tells you whether the agent is working at a basic level before you go deeper.

Global Filters

Agent / Type
Filter by specific agent or use case. Use this to compare performance across multiple agents and identify which ones are underperforming.
Timeframe
Adjust the reporting window. Critical for measuring whether changes you made actually improved performance — always compare before vs. after.
Channel
Filter by Web, Mobile, Messaging, etc. Customer behavior differs significantly by channel — an agent that works well on web may struggle on mobile.
Subagent / Action
Filter by specific topic or workflow. Isolates performance for one part of the agent experience without noise from others.

Reading the Story — What These Numbers Tell You Together
High engagement (94%) + high abandonment (73%) + zero deflection = users are willing to try the agent, but it's not resolving their needs AND it's not routing them to a human either. They're engaging and then just leaving. The agent is broken in a very specific way: it's discoverable but not functional.
  • High abandonment → Drill into the Sessions tab to find the intents that led to abandonment. Build new topics to address the gaps.
  • Low deflection → Topic instructions or actions may be too narrow — expand coverage so the agent can actually resolve requests.
  • 0% escalation + high abandonment → Users may want to escalate but can't. Review whether the escalation path is configured correctly.
  • Fast deflection time → When the agent works, it works fast. Use that as a benchmark for what good looks like once you fix the gaps.

Agent Usage Overview

Bar chart showing session volume per agent — identifies most-used and highest-risk agents.
What it shows
Session counts broken out by agent. Helps identify which agents are getting the most traffic and which ones have disproportionate abandonment or escalation.
NOT_SET flag
Sessions appearing as "NOT_SET" (no agent name) signal a data quality issue — likely agents built on the wrong template, or Session Tracing wasn't active before those sessions ran.
How to Use This

Sort by highest volume. Focus your optimization effort there first — fixing a high-traffic agent with low deflection has 10x the impact of fixing a low-traffic one. Investigate NOT_SET sessions by verifying agent template and confirming the Data Kit was fully deployed before sessions began.

Agent Analytics Dashboard — Quality Tab

AI-generated quality scoring — evaluating response accuracy, relevance, and completeness by agent, topic, and intent
What this tab answers: When the agent responds, how good is the response? The Overview tab tells you whether the agent is working. The Quality tab tells you how well it's working when it does. These are different questions with different fixes.

Quality Score Scale

Scale
Quality scores use a 1–5 scale generated by AI analysis of each interaction.
Score RangeRatingWhat It Suggests

2 – 3LowPartially helpful but with significant gaps — prompts, grounding, or actions need work
3 – 4GoodMostly relevant and accurate — targeted refinements will push it higher
4 – 5HighStrong response quality — consistent, accurate, and well-grounded

The Story These Numbers Tell
The agent scores highest when it escalates to a human (3.67) — not when it resolves on its own. Every self-service topic is Very Low. This means the agent is engaging users but can't actually help them. The escalation path is the only thing working. This is a grounding and instruction problem, not a structural one.
  • Very Low scores across topics → Review topic instructions and grounding data. The LLM may not have enough context to respond well — check Knowledge article coverage.
  • High volume + low quality → Verify_Customers (45 sessions, 1.47) is the highest-ROI fix. Start there.
  • Escalation scores highest → Consider routing more intents to a human until the agent is better trained. Don't hide the escalation path.
  • NOT_SET subagents → 37 sessions with no topic name means missed routing. Check topic configuration and confirm Session Tracing was live before those sessions ran.
  • Use Custom Scorers (Beta) → If the default AI scoring doesn't reflect your specific use case, define your own scoring criteria to get more relevant quality signals.

Data Explorer — Intents Tab

What it is
Analyzes quality broken down by the specific customer intent — what the user was actually trying to accomplish.
Why it matters
Two users can use the same topic but have completely different intents. This tab tells you which specific requests are succeeding and which are failing — a level of precision the subagent view can't give you.
How to Use This

Filter to your lowest-quality topics, then drill into Intents to find the specific requests causing failures. For each failing intent, check: Are the session traces showing a retrieval failure? A failed action? A misclassified request? Each root cause has a different fix.

Chapter 7

Optimization — Tagging & Intent Tags

How Agentforce surfaces patterns across thousands of sessions without you reading each one
What this covers: Tagging is the mechanism Agent Optimization uses to make sense of session volume at scale. Without tags, you have a list of transcripts. With tags, you have a map of what your users actually need — and where the agent is failing to deliver it.

How Tagging Works — The Flow

Step 1
Each session is broken into moments — one per distinct user intent within the conversation.
Step 2
Each moment receives an Intent Tag — an AI-generated label describing what the user was trying to accomplish (e.g., "Reset Password", "Check Order Status", "Verify Account").
Step 3
Tags with enough volume are grouped into System Tag Clusters — cross-session patterns that reveal what users consistently ask about, regardless of how they phrase it.

Critical Rules — What Students Must Know

RuleDetailWhy It Matters
Clusters are generated weekly Not real-time — batch process runs once per week Don't expect instant results after enabling Session Tracing
Minimum 50 moments required Clusters won't appear until 50+ moments exist Low-traffic orgs may not see tags for weeks
Minimum 30 days of data 30-day window required before clusters generate New orgs need patience — the system is learning
10+ moments per cluster A cluster only gets a tag if 10+ moments are associated Very rare intents won't surface as named clusters
Most common student/customer question: "Why don't I see any tags yet?" — Answer: You need enough volume (50+ moments) and enough time (weekly batch, 30-day minimum). Tags won't appear immediately after enabling Session Tracing. Set expectations with customers during implementation.

How to Use Tags Once They Appear

  • Find the highest-volume clusters → These are what your users care about most. If they don't have a mapped topic in the agent, build one.
  • Find clusters with low quality scores → These are intents the agent is attempting but failing. The tag name tells you the intent; the quality score tells you how badly it's failing.
  • Find clusters with no topic match → These are gaps — real user needs the agent can't currently address. Prioritize building topics for the highest-volume unmatched clusters.
  • Track clusters over time → A cluster that grows week-over-week and stays Very Low quality is a compounding problem. Fix it before it becomes your top abandonment driver.
